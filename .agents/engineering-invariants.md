# MoviePilot-TV 工程不变量

本文档将 `full-review-20260731-042646` 全量审计及后续修复中已证实的共性根因，转为编码与 Review 时可执行的规则和反例。它不是历史缺陷队列，也不证明当前每条生产路径都已完全满足这些条件。

使用原则：

- 仅读取与当前任务有关的章节，不要为了保险加载全文。
- 新增行为和本次实际改动的部分必须遵守对应不变量；已有明确接受的例外只需确认本次没有扩大，不得因读到本文档就自动重开或顺手修复。
- 若当前实现与本文档冲突，先核对产品意图、当前上游合同及审计归档，不要顺手扩大修复范围。
- 每节的复发模式与 finding 编号用于按需定位证据，不表示全部同类问题仍未修复；已驳回或未验证的候选不能直接升级为强制规则。
- 验证项是按改动风险选取的反例，不是每次修改都必须跑完的全量矩阵。优先复用现有机制与测试，不为清单新增框架。
- 精确历史证据、已跳过风险和未运行验证边界以 `.agents/audits/full-review-20260731-042646/` 为准。

## 1. 会话、权限与异步发布

复发模式：只在页面末尾检查账号，内部请求、缓存、重登或持久化已先写入错误会话（F-027、F-062、F-063、F-146）。

### 规则

- 跨 `await` 的请求必须在启动前冻结会话、请求代际和业务目标，并在每个可见状态发布前复核。
- session epoch 必须单调。A→B→A 不能只靠 base URL、用户名或权限集合相等来判定“还是原会话”。
- 父 ViewModel 的最终 gate 不能代替子 Paginator、子 ViewModel、error、loading 或缓存写入点的就地 gate。
- 取消必须传播到后续阶段。宽 `catch` 不得吞掉取消后继续启动下一轮请求或发布 ready。
- 重登、切换服务器或权限变化后，必须重验权限与当前身份；不得复用旧会话的 settings、profile 或长期页面快照。
- 自动重登、原请求重试和多阶段 mutation 必须沿用发起 owner；不能拿新账号凭据续跑旧动作。辅助徽章/探测请求是否允许触发重登或登出须在调用点明确，不能继承不合适的默认副作用。
- 持久化凭据必须属于同一 session revision，明确 Keychain、既有 fallback 与登出标记的读取权威；区分不存在和读取失败，删除失败不得让旧会话在重启后复活。
- 普通权限按已知键验证合法 Bool；坏项不能拖垮其他合法权限，也不能被宽松转成授权。未知能力不是“已启用”。

### 验证

- 涉及异步归属时覆盖相关的 A 慢/B 快、A→B→A、登出/撤权、离页取消和子对象提前发布。持久化改动另验写入/删除失败后的重启恢复。
- 断言不仅检查最终数组，还要检查 error、loading、focus、缓存和子观察对象是否被旧 owner 污染。

## 2. 业务身份与模型保真

复发模式：字段名看起来相同就互换身份；模型能解码却在投影/重编码时丢字段；一项合法稀疏数据拖垮整批（F-007、F-011、F-022、F-064、F-079、F-202）。

### 规则

- 明确区分 SwiftUI 渲染 `id`、后端业务 ID、来源原生 media ID、canonical 身份与缓存 key；不得互换使用。
- 媒体身份须保留来源 owner 与原生 ID；季订阅、删除和缓存链还必须保留 season。
- 持久快照和破坏性操作必须使用稳定、唯一、符合合同的业务身份。动态 UUID、可更名的展示文字和可重复 title 只能用于 fail-open 展示，不得用于判定同一对象。
- `nil`、缺字段、0、空串与非法值不能为了方便折叠成同一状态。Swift 属性默认值不是 `Decodable` 缺键默认。
- 明确非负季号才能建立分季身份；缺失、`null` 或负值不得折叠成 S00。
- 对上游已声明且生产链真正消费的字段，强类型解码再编码不得静默丢失；只有证实存在通用透传合同时才保留整块 raw payload。
- 按端点合同逐个验证候选身份后再 fallback；无效的 0、负值或空串不得遮蔽后续合法候选，也不能把某端点的正 ID 规则无差别推广到所有模型。
- 后端允许缺失/null 的展示字段和可选嵌套值，应在 DTO 边界局部降级，保留同批合法数据；不要批量 Optional 化、静默丢整条记录，或放松 mutation 身份/权限/成功标记的验证。
- GET→编辑→PUT/POST 必须保留合同要求的字段与原值；未修改保存应保持语义不变，显式清空须区分省略、null、空数组和 0。上游新增可写字段时，先补模型或按正式合同保留，再允许完整对象更新。
- 详情补全按字段合同合并；稀疏回包不得抹掉已有有效展示值，展示字段补全也不能悄悄更换 route owner。解码过程不得读取 MainActor 全局配置；传输值和依赖当前配置的派生值分开。
- 通用响应解包先拒绝显式 `success:false`，再消费 data，不能因 data 可解就发布成功或写入缓存（F-082）。读取接口的缺 success/原生响应兼容边界与 mutation 的严格成功合同分别处理。

### 验证

- 对照后端 schema、配套 Web 的实际身份选择顺序和 TV 全部消费者。
- 为跨来源同号、同媒体不同季、同名作品、缺 ID、0/负数、字段名与分隔符碰撞建立反例。
- 解码使用“合法完整项 + 合法稀疏项”同批 fixture；保存覆盖未编辑往返、显式清空和只改一个字段，断言实际请求体及持久语义。

## 3. 缓存、预载与生命周期

复发模式：只清缓存、不刷新已发布状态；相同 URL 被视为相同授权；预载任务与实际使用者生命周期脱节（F-008、F-019、F-020、F-026、F-071、F-100、F-118、F-243）。

### 规则

- 会话数据缓存必须绑定 session namespace；切换会话时旧请求不得回填新 owner 可见的 key。
- 同 key 并发采用 latest-wins 时，旧结果必须在“返回给调用者”和“写入共享缓存”两处都失效。这不要求每次普通读取都启动新请求；同一会话和缓存代际内、参数一致的读取可以合并复用在途请求。`APIService` 的接口缓存统一经 `sessionCachedValue` 使用 `CoalescingCache`：它负责在途合并、强刷取代、代际失效与会话校验；新增同类缓存直接复用，不再手写 owner/revision/generation。
- 多个页面或导航栈共享预载任务时，owner 必须稳定且可计数；只有最后一个 owner 离开才能释放保护。
- 可取消的 handle 型工作必须原子交接“取消状态 + handle”：取消早于 handle 安装时，安装者也必须立即取消；发布 ready 前再检查父任务。
- 同一 canonical 媒体可能同时存在多个 UI/cache alias。操作结果需要同步全部已知 alias 时，不得用 `first(where:)` 假定唯一命中。
- 图片 processor 必须按实际显示尺寸 downsample；额外 raster 步骤必须用 Instruments 或可量化基线证明价值。
- 受保护图片的 cache、in-flight 合并、Cookie 和下载器须遵守同一会话边界；预取与正式显示使用一致的认证选项。公共图片继续按既有合同共享，不能无差别清除无关 Cookie/缓存。
- 缓存失效不等于已发布 UI 状态刷新。mutation 成功、页面重新进入/回前台或来源变化时，按该入口合同同步相关快照与派生状态；会影响后续动作的 availability、订阅状态等不能只刷新其中一项。
- 检查 owner→长期 task/fetcher/回调→owner 的强引用环；一次性任务完成后退休，延迟预载和轮询遵守离页/切会话取消，`onDisappear` 不能直接等同于导航 owner 已释放。

### 验证

- 分别断言返回值、缓存值和已发布 UI 值；覆盖较新强刷先完成、跨账号同 URL、mutation 后页面仍存活、回前台发现外部变化。
- 生命周期改动检查多 owner 共用、最后一个 owner 释放、缓存命中/未命中与取消后迟到回调；资源驻留和性能结论用量化证据支持。

### 边界

- 早取消/handle 安装（`F-117`）与 canonical alias 全量回写（`F-119`）在本轮审计中存在用户明确接受的现存例外；具体裁决见归档 `final-report.md` 的对应编号。新修改不得默认这些例外已消失，也不得顺手扩大。

## 4. Mutation、确认与破坏性操作

复发模式：UI 表达一种意图，执行时重新选择目标/动作；HTTP 成功被误当业务完成；旧回调改新操作状态（F-075、F-083、F-092、F-124、F-152、F-156、F-193、F-245）。

### 规则

- 展示预览或确认页时就冻结不可变 intent：精确目标、owner、session、season/范围、命中数和对象签名。确认后不得从实时选择或可重用整数 ID 重新解析目标。
- single-flight/busy 状态必须归属于具体 operation 和 target，不得用一个页面级 Bool 吞掉其他对象的操作或让旧 defer 清新任务状态。
- 临时创建或可复用对象必须保留 created/reused receipt；只能回滚当前 operation 真正创建且仍属于当前 session 的对象。
- HTTP 2xx 不等于业务成功。Mutation 按端点合同验证响应；声明 `success` 的端点必须显式为 `true`，必要 ID/预览明细缺失或非空 body 不可解时失败关闭。空体只按明确 no-content 合同接受，不能靠通用空体/解码失败 fallback 报成功。
- 删除任务与删除已下载文件必须是两个显式动作；不可撤销的范围必须单独确认并使用清晰动作词。
- 客户端菜单、Tab 或路由隐藏不是安全边界。manage-only 资源的读取和 mutation 必须由后端按 token subject 与对象 owner 校验。
- 已展示的“订阅/取消”“开始/暂停”意图不能因点击后重查而反转；状态变化应拒绝旧意图并刷新。成功回写使用冻结的目标状态或权威刷新，不对已被轮询更新的值 `toggle()`。
- 同一目标需要防重入时，在首个 await 或可重入窗口前原子占用操作门禁；若动作入口到设 busy 之间仍能重复启动任务，应在入口同步拦截。
- 已受理不等于已完成。端点能提供逐项结果时记录已受理、失败和未知项，重试不重复已确认受理项；只有整批结果时不在客户端臆造逐 ID 状态，沿用合同和既有裁决。

### 验证

- 覆盖双击/快速重入、确认后切换选择、关闭 Sheet、切账号、超时迟到回调、部分成功、重复 ID 和畸形 2xx。
- 破坏性验证必须分离于个人真实后端的默认只读套件，显式开关并尽力恢复现场。

## 5. 分页、SSE 与可恢复状态

复发模式：把空批、EOF、失败、取消和未完成折叠成成功；并发启动后仍被辅助阶段阻塞；增量插入代替权威对账（F-033、F-080、F-126、F-142、F-149、F-204、F-221、F-225）。

### 规则

- offset 分页依赖稳定全序；TV 可控的主排序字段可重复时应加稳定唯一 tie-breaker。若不稳定顺序属于 Web/TV 共享的后端合同，记录上游风险，不用客户端去重或“遇已知即停”伪装修复。
- 一轮内部扫描回空但仍 `hasMore == true` 时，不得被外层 Paginator 判为永久终页。
- SSE 必须按空行组帧，多个 `data:` 行以换行拼接，并明确处理 CRLF、CR-only、BOM 与无终止尾帧。
- SSE 的逐字节读取、组帧和解码必须离开 MainActor，仅在完整事件交付时切回做会话/取消校验与状态发布；执行器切换必须保留父任务取消传播，不能只凭 `nonisolated` 声明推定已离开调用者执行器。
- 正常 EOF、业务终态、网络断开、取消和切服必须分流。只有明确需要持续监听的流才允许有界重连。
- error、success-empty、stale-data 和 loading 是不同状态。新增或修改恢复路径时要明确用户如何重试；`F-187`（资源搜索错误/空终态需退出重进）的已接受例外不因本条自动重开。
- 只有明确成功终止才能进入 missing-sites 等受限补偿；补偿合并必须保留稳定身份并去重。
- 空闲、运行中、无结果、不可用和已完成必须能收敛到相应终态；`hasLoaded/hasSearched/ready` 不得在失败或取消后永久锁住恢复。未支持的媒体类型不能进入永远无法 ready 的详情/预载分支。
- 核心内容和辅助请求分清依赖：可选分享、图片、徽章或剧集组不能无界阻塞已可用的核心结果。并发多块数据须明确整组原子发布还是逐块隔离错误，不能固定 await 顺序后半途留下混合快照。
- 增量轮询不等于权威对账；按页面激活/刷新合同处理外部删除、同 ID 内容替换和状态变化，不能仅“遇已知 ID 即停”就宣布列表完整。
- 去重使用与最终列表一致的稳定身份，覆盖已有数据和当前批次；软过滤置尾等产品排序语义须贯穿首次排序和用户重排，不能被后续 sort 覆盖。

### 验证

- 分页 fixture 要覆盖同秒/同排序值跨页、过滤后空批、删除后补位与旧结果返回。
- SSE 用例要分别覆盖 framing、终态、clean EOF、临时断开、取消和切服；不得用只看请求次数的测试代替事件语义。
- 多阶段加载验证辅助请求慢/失败、部分成功、取消后重入和 partial→full 身份补全；轮询验证外部删除与同 ID 替换，不能只测新增行。
- 修改 SSE 读取或执行器边界时，必须使用 URLProtocol 等本地传输替身，经生产 API 入口验证缓冲流吞吐与完整事件数量，并与相同载荷的基线比较耗时；纯 framing 单测不能证明执行器性能。参考 `MoviePilot-TV-Tests/SSEStreamTests.swift` 中的吞吐回归用例。

## 6. tvOS 呈现、焦点与可访问性

复发模式：控件视觉上存在，但遥控器/辅助功能无法完整操作；忽略模态、加载和系统版本带来的实际状态差异（F-162、F-164、F-169、F-176、F-191、F-241）。

### 规则

- 主操作优先使用原生 `Button`、`disabled` 语义与稳定 `id`；不要用透明手势、动态 UUID 或布局占位冒充可聚焦控件。
- Sheet、Alert 或其他模态展示时，底层 Menu/exit observer 和焦点处理必须禁用；关闭动画窗口还要检查 presented view controller。
- 新增或修改焦点恢复时必须明确其生命周期 owner，不能未验证地假定某个 dismiss/刷新时序一定只需尝试一次；`F-205`（Reorganize 刷新期间焦点恢复调用被丢弃）已暂缓，本条不自动重开该例外。
- 非活动页、透明层和被模态覆盖的控件必须同时退出 focus 与 accessibility tree。
- 长文本和长路径必须有原生可滚动、可聚焦或可完整读取的入口。字体、Reduce Motion 和对比度使用平台能力，不建立平行系统。
- 图片占位与媒体类型语义分离：未知/缺失类型使用中性图标，不得伪装成电影或电视剧。
- 共享控件/样式修改须检查所有 Sheet 与系统版本分支；加载、成功、失败、缺图应保留一致的布局边界，不能只验证缓存命中或最新系统的一条路径。

### 验证

- 静态源码守卫测试只能证明接线，不能证明 Focus Engine 事件顺序、实际可达性或视觉结果。
- 涉及焦点、VoiceOver、Reduce Motion、最大字号、旧 tvOS 样式或滚动性能时，必须记录真机/目标 runtime 未验收边界；不得把静态推断写成运行通过。

## 7. 上游合同与服务端边界

复发模式：根据接口名字、独立前端 HEAD 或请求次数推断兼容，遗漏真正执行的版本、来源、权限与筛选域（F-070、F-192、F-209、F-210、F-246）。

### 规则

- 兼容目标由 MoviePilot 后端发布版本决定，Web 必须使用该后端 `FRONTEND_VERSION` 指定的配套标签；不得把前端独立 HEAD 当成部署合同。
- 先从后端 schema、端点、权限与持久化追到配套 Web 的真实调用和用户结果，再映射 TV 入口；不能只比字段名或请求体。
- 若 Web 同样不发请求、同样失败或明确依赖后端修复，默认记录为上游风险，不在 TV 单端发明差异化兜底。
- 来源、站点、默认/全部/显式子集必须分流；用户可见筛选域以后端声明且真实执行的权威域为准。
- 兼容 checklist 是历史风险索引，不是审查范围。未命中 checklist 不能推导“无影响”。
- 选项和筛选值只能按对应业务的权威域归一化；降级响应、网络失败或无权限读到的子集不能当作完整域，进而删除用户已有合法选择。


### 验证

- 选择与目标发布版本相符的 schema/Web fixture，核对最终来源、筛选范围、权限与用户结果；覆盖默认/全部/子集及权威域/降级域，不能仅断言 query 存在或请求发出。

### 路由

- 订阅契约：`docs/subscription-compatibility-checklist.md`
- 真实后端测试：`docs/backend-compatibility-tests.md`
- 上游更新流程：`.agents/prompts/frontend-update.md`

## 8. 日志、反馈与测试诚信

复发模式：错误只进日志，用户无从恢复；测试验证内部表象，没有覆盖用户入口、真实生产调用和失败时序（F-049、F-060、F-087、F-126、F-201）。

### 规则

- 生产日志统一使用 `Logger`，不得新增直接 `print`。
- 日志或用户错误文本不得直接泄露 token、Cookie、密码等凭据；新增输出时检查 URL/query 和服务端错误是否携带敏感值。
- `NotificationManager` 用于需要用户干预的失败；成功默认用 UI 状态变化表达，不发全局成功通知。Sheet 内操作优先使用 Sheet 内可见反馈。
- 服务端错误字段按本地化优先级选择首个有效非空文本，空白首选值不能遮蔽后续有效错误；必要长错误须能完整读取。
- 测试必须从能区分修复前后的状态起步。只断言新 ViewModel 的初始值、只搜源码字符串或只验请求次数，不能单独证明业务回归。
- 回归 fixture 必须保留真正的触发条件：缺 ID 就不要由默认 fixture 补 ID，乱序就让旧请求实际晚到；通过实际生产入口验证请求、子状态/缓存及用户结果，不能用入口不可达的 helper 调用代替。
- 新增回归测试时，在安全可行的情况下做反向验证：临时还原缺陷或去掉守卫，确认新用例确实转挂，再恢复修复。
- 本项目只以 `xcodebuild` 的 tvOS App scheme 为构建/测试依据；`swift build/test` 不能代替。
- 定向测试、影响套件、完整套件、真实后端、真机和 Instruments 是不同证据层级；未运行必须直说，真实后端网络/图片噪声不得伪装成代码通过或代码失败。
- 涉及审计 finding 的修复，在主代理实现和验证后，使用一名未参与实现的独立复核者检查回归、范围和验证诚信。

## 9. 请求编码与 URL 边界

复发模式：把不同协议的字符串当作同一种文本拼接/转义，特殊字符改写参数或路径，图片替换误伤第三方 URL（F-084、F-086、F-088、F-103、F-104、F-105）。

### 规则

- baseURL 在统一入口规范化，保留反向代理 path-prefix；API、SSE 和图片复用对应构造 helper，不各自拼字符串。
- 不透明媒体/人物 ID 在 API 边界按单一路径段编码一次；调用者不拆分、不重复转义，也不从任意标题正则猜测它应走标题搜索还是 ID 路由。
- URL query 与 `application/x-www-form-urlencoded` 按各自接收端的解析规则编码；字面 `+`、`&`、`=`、`%`、空格和非 ASCII 值必须往返保真，不能直接把 query 字符串当登录表单 body。
- 复合 query 值按目标 Web/后端已确认的形状编码；不得把数组/对象随手 JSON 化或改成单值。没有真实合同的插件能力先保留未验证边界，不实现通用表单框架。
- URL 改写只作用于已确认的 host/path 结构；第三方地址、query 和签名保持原语义。相对图片地址通过共享 helper 解析，不能在 View/模型中复制代理规则。

### 验证

- 用本地传输替身核对最终 URL/body 经接收端规则解码后的值，覆盖特殊字符、非 ASCII、已编码值与反代前缀；只看拼接字符串或请求次数不够。

## 10. 表单、派生状态与展示一致性

复发模式：UI 显示值、内存草稿、实际提交值和观察链不是同一语义；初始正常，切换选项/来源或详情补全后才出错（F-061、F-085、F-114、F-145、F-170、F-199、F-227、F-229、F-240）。

### 规则

- 表单打开后不修改直接保存，应保持原语义；允许选择某值的控件也要允许恢复原有“自动/默认/未指定”状态。未知统计不能显示成真实 0，未知媒体类型不能因“不是电影”被当作电视剧。
- 明确即时生效与确认提交：即时修改外部状态的关闭动作应表达“完成”；声称可取消的编辑必须有草稿/提交边界，不能 Menu/Exit 后仍悄悄保存。
- 切换媒体类型、来源、下载器或目录时，检查旧筛选与隐藏字段是否仍适用，按正式合同构造最终请求。复合目标应一起更新，不能靠 debounce 事后补齐 owner。现有 Web 共享行为及 F-212/F-213 等已接受例外不因本条自动改变。
- 已保存但当前选项域不可见的值，应有符合产品合同的展示/清除方式；不能悄悄提交用户无法发现的值，也不能无授权裁剪。显示名称可更改或重复，Picker/配置寻址仍须使用稳定身份。
- 展示、过滤、排序与选择准入复用同一规范化语义；可展示候选先过滤/去重再截断。仅在字段合同允许时 trim/转大小写，显示层清理不能改写正则、凭据、路径或其他需保真的提交值。
- `@Published` 持有子 `ObservableObject` 不代表子变化会被父 View 观察；显式观察或复用已有事件转发。依赖配置/来源/完整详情的派生值，须在依赖变化时更新，不能长期冻结初始化快照。
- 共享 formatter/parser 只在单位、locale、时区和空值语义一致时复用；固定正则/昂贵格式器不在高频渲染路径重复创建，性能优化保留量化依据。
- 协议年份、数值与枚举按业务合同生成，不直接采用设备显示日历；标题中的数字只按已确认的查询语法解释，不能见到四位数字就当年份（F-131、F-141）。

### 验证

- 从有值的现有对象出发验证原样保存、清空、恢复默认、类型/来源切换、隐藏选项清除和只改一字段；检查最终 payload，不只检查控件绑定。
- 改变子对象、排序、当前配置或稀疏详情，验证最终展示/业务消费者同步变化；tvOS 可达性与视觉结果仍按 §6 披露运行验收边界。
