# MoviePilot-TV 工程不变量

本文档沉淀自 `full-review-20260731-042646` 全量审计及后续修复，用于约束今后的高风险修改与代码审查。它不是历史缺陷队列，也不证明当前每条生产路径都已完全满足这些理想条件。

使用原则：

- 仅读取与当前任务有关的章节，不要为了保险加载全文。
- 新增行为和本次实际改动的部分必须遵守对应不变量；已有明确接受的例外只需确认本次没有扩大，不得因读到本文档就自动重开或顺手修复。
- 若当前实现与本文档冲突，先核对产品意图、当前上游合同及审计归档，不要顺手扩大修复范围。
- 精确历史证据、已跳过风险和未运行验证边界以 `.agents/audits/full-review-20260731-042646/` 为准。

## 1. 会话、权限与异步发布

### 规则

- 跨 `await` 的请求必须在启动前冻结会话、请求代际和业务目标，并在每个可见状态发布前复核。
- session epoch 必须单调。A→B→A 不能只靠 base URL、用户名或权限集合相等来判定“还是原会话”。
- 父 ViewModel 的最终 gate 不能代替子 Paginator、子 ViewModel、error、loading 或缓存写入点的就地 gate。
- 取消必须传播到后续阶段。宽 `catch` 不得吞掉取消后继续启动下一轮请求或发布 ready。
- 重登、切换服务器或权限变化后，必须重验权限与当前身份；不得复用旧会话的 settings、profile 或长期页面快照。

### 验证

- 至少覆盖 A 慢/B 快、A→B→A、登出/撤权、离页取消和子对象提前发布。
- 断言不仅检查最终数组，还要检查 error、loading、focus、缓存和子观察对象是否被旧 owner 污染。

## 2. 业务身份与模型保真

### 规则

- 明确区分 SwiftUI 渲染 `id`、后端业务 ID、来源原生 media ID、canonical 身份与缓存 key；不得互换使用。
- 媒体身份须保留来源 owner 与原生 ID；季订阅、删除和缓存链还必须保留 season。
- 持久快照和破坏性操作必须使用稳定、唯一、符合合同的业务身份。动态 UUID、可更名的展示文字和可重复 title 只能用于 fail-open 展示，不得用于判定同一对象。
- `nil`、缺字段、0、空串与非法值不能为了方便折叠成同一状态。Swift 属性默认值不是 `Decodable` 缺键默认。
- 明确非负季号才能建立分季身份；缺失、`null` 或负值不得折叠成 S00。
- 对上游已声明且生产链真正消费的字段，强类型解码再编码不得静默丢失；只有证实存在通用透传合同时才保留整块 raw payload。

### 验证

- 对照后端 schema、配套 Web 的实际身份选择顺序和 TV 全部消费者。
- 为跨来源同号、同媒体不同季、同名作品、缺 ID、0/负数、字段名与分隔符碰撞建立反例。

## 3. 缓存、预载与生命周期

### 规则

- 会话数据缓存必须绑定 session namespace；切换会话时旧请求不得回填新 owner 可见的 key。
- 同 key 并发采用 latest-wins 时，旧结果必须在“返回给调用者”和“写入共享缓存”两处都失效。
- 多个页面或导航栈共享预载任务时，owner 必须稳定且可计数；只有最后一个 owner 离开才能释放保护。
- 可取消的 handle 型工作必须原子交接“取消状态 + handle”：取消早于 handle 安装时，安装者也必须立即取消；发布 ready 前再检查父任务。
- 同一 canonical 媒体可能同时存在多个 UI/cache alias。操作结果需要同步全部已知 alias 时，不得用 `first(where:)` 假定唯一命中。
- 图片 processor 必须按实际显示尺寸 downsample；额外 raster 步骤必须用 Instruments 或可量化基线证明价值。

### 边界

- 早取消/handle 安装与 canonical alias 全量回写在本轮审计中存在用户明确接受的现存例外。新修改不得默认这些例外已消失，也不得顺手扩大。

## 4. Mutation、确认与破坏性操作

### 规则

- 展示预览或确认页时就冻结不可变 intent：精确目标、owner、session、season/范围、命中数和对象签名。确认后不得从实时选择或可重用整数 ID 重新解析目标。
- single-flight/busy 状态必须归属于具体 operation 和 target，不得用一个页面级 Bool 吞掉其他对象的操作或让旧 defer 清新任务状态。
- 临时创建或可复用对象必须保留 created/reused receipt；只能回滚当前 operation 真正创建且仍属于当前 session 的对象。
- HTTP 2xx 不等于业务成功。Mutation 只接受端点声明的合法 envelope；非对象、缺 `success`、非 `true` 或缺必要 ID 时失败关闭，空体只按明确 no-content 合同接受。
- 删除任务与删除已下载文件必须是两个显式动作；不可撤销的范围必须单独确认并使用清晰动作词。
- 客户端菜单、Tab 或路由隐藏不是安全边界。manage-only 资源的读取和 mutation 必须由后端按 token subject 与对象 owner 校验。

### 验证

- 覆盖双击/快速重入、确认后切换选择、关闭 Sheet、切账号、超时迟到回调、部分成功、重复 ID 和畸形 2xx。
- 破坏性验证必须分离于个人真实后端的默认只读套件，显式开关并尽力恢复现场。

## 5. 分页、SSE 与可恢复状态

### 规则

- offset 分页依赖稳定全序；TV 可控的主排序字段可重复时应加稳定唯一 tie-breaker。若不稳定顺序属于 Web/TV 共享的后端合同，记录上游风险，不用客户端去重或“遇已知即停”伪装修复。
- 一轮内部扫描回空但仍 `hasMore == true` 时，不得被外层 Paginator 判为永久终页。
- SSE 必须按空行组帧，多个 `data:` 行以换行拼接，并明确处理 CRLF、CR-only、BOM 与无终止尾帧。
- 正常 EOF、业务终态、网络断开、取消和切服必须分流。只有明确需要持续监听的流才允许有界重连。
- error、success-empty、stale-data 和 loading 是不同状态。新增或修改恢复路径时要明确用户如何重试；已裁决为“退出重进即可恢复”的现有例外不因本条自动重开。
- 只有明确成功终止才能进入 missing-sites 等受限补偿；补偿合并必须保留稳定身份并去重。

### 验证

- 分页 fixture 要覆盖同秒/同排序值跨页、过滤后空批、删除后补位与旧结果返回。
- SSE 用例要分别覆盖 framing、终态、clean EOF、临时断开、取消和切服；不得用只看请求次数的测试代替事件语义。

## 6. tvOS 呈现、焦点与可访问性

### 规则

- 主操作优先使用原生 `Button`、`disabled` 语义与稳定 `id`；不要用透明手势、动态 UUID 或布局占位冒充可聚焦控件。
- Sheet、Alert 或其他模态展示时，底层 Menu/exit observer 和焦点处理必须禁用；关闭动画窗口还要检查 presented view controller。
- 新增或修改焦点恢复时必须明确其生命周期 owner，不能未验证地假定某个 dismiss/刷新时序一定只需尝试一次；现有已暂缓或接受的焦点时序例外不因本条自动重开。
- 非活动页、透明层和被模态覆盖的控件必须同时退出 focus 与 accessibility tree。
- 长文本和长路径必须有原生可滚动、可聚焦或可完整读取的入口。字体、Reduce Motion 和对比度使用平台能力，不建立平行系统。
- 图片占位与媒体类型语义分离：未知/缺失类型使用中性图标，不得伪装成电影或电视剧。

### 验证

- 静态源码守卫测试只能证明接线，不能证明 Focus Engine 事件顺序、实际可达性或视觉结果。
- 涉及焦点、VoiceOver、Reduce Motion、最大字号、旧 tvOS 样式或滚动性能时，必须记录真机/目标 runtime 未验收边界；不得把静态推断写成运行通过。

## 7. 上游合同与服务端边界

### 规则

- 兼容目标由 MoviePilot 后端发布版本决定，Web 必须使用该后端 `FRONTEND_VERSION` 指定的配套标签；不得把前端独立 HEAD 当成部署合同。
- 先从后端 schema、端点、权限与持久化追到配套 Web 的真实调用和用户结果，再映射 TV 入口；不能只比字段名或请求体。
- 若 Web 同样不发请求、同样失败或明确依赖后端修复，默认记录为上游风险，不在 TV 单端发明差异化兜底。
- 来源、站点、默认/全部/显式子集必须分流；用户可见筛选域以后端声明且真实执行的权威域为准。
- 兼容 checklist 是历史风险索引，不是审查范围。未命中 checklist 不能推导“无影响”。

## 8. 日志、反馈与测试诚信

### 规则

- 生产日志统一使用 `Logger`，不得新增直接 `print`。
- `NotificationManager` 用于需要用户干预的失败；成功默认用 UI 状态变化表达，不发全局成功通知。Sheet 内操作优先使用 Sheet 内可见反馈。
- 测试必须从能区分修复前后的状态起步。只断言新 ViewModel 的初始值、只搜源码字符串或只验请求次数，不能单独证明业务回归。
- 新增回归测试时，在安全可行的情况下做反向验证：临时还原缺陷或去掉守卫，确认新用例确实转挂，再恢复修复。
- 本项目只以 `xcodebuild` 的 tvOS App scheme 为构建/测试依据；`swift build/test` 不能代替。
- 定向测试、影响套件、完整套件、真实后端、真机和 Instruments 是不同证据层级；未运行必须直说，真实后端网络/图片噪声不得伪装成代码通过或代码失败。
- 涉及审计 finding 的修复，在主代理实现和验证后，使用一名未参与实现的独立复核者检查回归、范围和验证诚信。
